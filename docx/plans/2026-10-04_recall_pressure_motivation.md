# FluidCKPT：动机实验与三组件论证

开发编号：v0.1.23.2。建立日期：2026-10-04。本文采用 anti-defensive-writing 的直接论证方式。

## 1. 从需求到机制

LLM 服务切换使权重的计算需求与保存需求分离。A 暂停后，它的权重仍会被再次使用，而原有 HBM 需要交给 B 和 KV cache。服务系统因此需要同时完成两件事：及时归还昂贵的计算内存，并保留 A 下一次快速返回的条件。

集群已经拥有可承接这些权重的 DRAM、HBM 和 SSD。这些空间分布在不同节点和 NUMA 域，请求又会改变恢复位置。同样多的保活字节，由于位置、共享链路和 TP rank 的差异，可以产生不同的恢复时间。把每层缓存和每次传输分别优化，会遗漏保存位置对未来恢复的影响。

FluidCKPT 将已物化权重作为集群对象管理。对象先获得独立于计算进程的所有权，再根据恢复代价选择位置，最后通过维持覆盖的分块迁移建立新布局。恢复请求直接使用当前已提交的片段，从多个位置重新组成模型。

## 2. 三个组件及其依赖

### C1：独立所有权的权重对象

保存不可变版本、处理后 storage/view 布局及片段覆盖。CPU owner 和 SSD extent 持有实际字节，计算进程和传输进程持有有期限的访问关系。这个接口让 A 的 HBM 可以被释放，同时让原有处理后权重继续可寻址。

对应实验：释放物理 HBM 后 B 成功服务；传输进程重建后完整 GLM 的已保存块仍可接管和恢复。记录最后副本发布、读者退出、实际内存回收三个不同的完成时刻。

### C2：恢复代价驱动的放置

利用目标设备组、NUMA 拓扑、实际路径容量和未来请求场景，选择片段位置与副本数量。放置的价值由模型恢复关键路径决定；TP rank 的互补性和共享瓶颈共同影响一个缓存片段的收益。MILP 描述离散位置选择，资源 LP 描述给定副本下的供给分配。

对应实验：同预算、同搬运实现的简单放置与联合放置对比，并交叉使用简单来源选择和资源 LP。目标是观察实际决策变化及其恢复收益。

### C3：让位与召回的联合执行

将布局变更拆成可独立发布、可独立释放的块。每一步在新覆盖完成后回收旧空间；恢复请求在块边界接管带宽并使用已经发布的混合布局。执行同时受临时空间、迁移链路和前台服务资源约束。

对应实验：A 下放时 B 服务；迁移 25/50/75% 请求 A，记录请求到首个正确 token、实际来源和前台 SLO。块间生成用于功能验收，独立持续负载用于并发干扰测量。

这三个组件依次提供“可以迁移”“迁往哪里”“如何及时完成”的能力。实验将分别测量所有权、放置和执行的作用。

## 3. 第一组动机实验：本地内存减少后，权重还能多快回来

研究问题：在相同完整后备容量下，本地可保留的权重减少时，集群 DRAM 能否避免恢复代价转为 SSD 路径主导？

- 模型：真实 Qwen3.6-35B-A3B，TP2；复用完整 GLM/Qwen 生命周期中已经捕获的运行时权重。
- 计算目标：node27 GPU0/1；迁移目标：node29 GPU0/1 对应的 DRAM keeper。node28 继续持有 GLM 后备，整条轨迹使用三节点。
- 横轴：实际保留在 node27 DRAM 的 Qwen 字节 / Qwen 完整运行时权重字节。首轮 100%、约 50%、0%，按 256MiB 块取整并报告实际值。
- 纵轴：恢复请求发出到收到首个正确 token 的秒数。
- 曲线一：本地 DRAM + node27 本地 SSD，作为匹配 warm engine 和处理后格式的分层回退基线。
- 曲线二：本地 + 远端 DRAM。双方使用相同恢复执行代码、完整对象、设备组和实际物理环境，只改变可选择的来源。
- 辅图：各点从 SSD 请求的逻辑字节和 SSD 服务进程实际 kernel read_bytes，用于说明缓存与真实存储 I/O 的关系。

所有点保留一份完整 DRAM 覆盖和相同的完整 SSD 后备；改变的是 DRAM 的位置。远端曲线使用迁走的已提交块，本地回退曲线从同一 SSD 底本补齐缺失范围。新的远端副本建立并验证后才退役本地块，迁移暂存峰值单独记录。其他 GLM 后备及服务预留保持相同。

本组实验解释本地容量与恢复位置之间的冲突，联合规划的额外收益由 C2 的 2×2 消融回答。

首轮每格一次，采用交错策略顺序定位容量效应；结果以实测点呈现。正式统计轮次在定位主导差异后登记。恢复检查32-token确定性输出；SSD底本和迁移块在发布前校验完整字节。

## 6. 先导结果与配对补强

capacity03生命周期已通过：GLM在约25/50/75%迁移位置的恢复首token为11.840/11.517/13.222s，最终为11.680s；Qwen对应返回约2.02–2.14s。两次GLM全量SHA覆盖784,208,680,448B，Qwen首次恢复SHA覆盖70,329,718,112B，所有生成一致。完整切换窗口包含同步观测/保存，另存lifecycle_analysis.json；曲线以预登记的恢复请求窗口绘制。

local_pressure02先导扫描已通过。100/约50/0%本地覆盖下，localDRAM+SSD分别3.072/31.439/63.328s，clusterDRAM分别1.869/2.606/3.286s。

100%点揭示了执行成本模型的问题：允许所有本地来源的LP分配了498,936,496B SSD读取，搬运1.854s；只用DRAM搬运0.995s。核查发现profile缺少serial_target_execution，而worker.execute按op依次完成传输。Cluster现在默认带上该执行约束；35GB CPU回归用例验证放宽并行假设会选SSD，匹配串行目标时选择完整DRAM，相关26项回归通过。固定启用成本的影响由后续配对测量区分。

cpu_first03复用相同SSD文件和DRAM字节，沿0→50→100%将块搬回node27，使用更强的DRAM优先基线：SSD候选只覆盖本地DRAM缺失的完整块。这样100%点的两策略输入完全相同。新曲线作为容量动机主图，先导曲线保留用于执行模型诊断。

serial_cost04已排队，等cpu_first03成功后，在100%本地DRAM和完整SSD都可选的相同状态下，按并行假设→串行约束→串行约束→并行假设运行四次。仅改变规划输入中的serial_target_execution，记录实际选择SSD字节、执行时间、首token及输出。此实验直接检验“执行代价改变来源选择”的机制。

本轮新图固定目标设备组。扩展到集群模型数量实验时，给基线相同的目标选择能力，或通过实际前台HBM占用明确哪些设备组可用；同时记录外部给定的放置约束。
