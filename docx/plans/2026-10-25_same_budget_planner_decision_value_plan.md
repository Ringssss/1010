# 同预算布局决策价值：强简单策略 vs 现有联合规划器

日期：2026-10-25。开发编号：v0.1.23.3 / task2，接续计划18.35与实验记录50.8。
对应后续总计划条目18.36、总记录51。**状态：事前设计，未启动任何新实验。**

本文登记下一阶段的完整口径，用于回答一个具体问题：**在完全相同的预算、候选集和执行器下，现有联合规划器选择的布局，是否比强简单策略选择的布局产生可测的、真实的 `weights_ready` 收益。** 本文不含任何新测量结论；所有前序数字均为已归档事实的引用。

| --- | ---: |

## 2. 研究问题：要证明什么，不证明什么

### 2.1 三级命题必须分开

对应联合规划必要性文章的三层论证：

1. **变量需要联合考虑**——已知成立（反例一二三）。
2. **某个具体简单算法失败**——已知成立（逐块排序、strict-positive 单步贪心有零收益平台期，见命题2）。
3. **值得建设/保留某个求解器**——**未成立，本文要检验的唯一命题**。

因此本轮的对照组必须包含**强**简单策略，而不是只打倒弱基线。若强简单策略与 joint 同解，结论就是"joint 无独有增量"，这是负结果，同样要如实记录并归档。

### 2.2 本轮明确不做的主张

- 不主张 joint 对所有简单方法占优（只对登记的策略集）。
- 不主张本轮差值可外推到未登记的内容/目标/预算/拓扑。
- 不把理论上限、LP 下界改善当作实机收益。
- 不把共同 outer 项的校正算作任何一方的算法收益——它同等地加在所有候选上，**不能制造排序优势**。
- 不把 `estimated_transfer_s`、`objective_s` 或 `bandwidth_lower_bound_s` 当 `weights_ready`。

## 3. 场景合同：同内容、同目标、同预算

### 3.1 固定不变的量（对所有策略完全一致）

- 模型内容：Qwen TP2，70,329,718,112B，66 extent，2096 个 32MiB chunk（末块按实际字节）。
- 硬件：node27 GPU4/5 为目标 TP2 双 rank，node30 GPU4 为唯一 sender；DRAM 两分片 NUMA4/7；单 sender 串行服务。
- 预算：目标 DRAM 192GiB / hard 224GiB，HBM 48GiB/card；helper DRAM 96 / hard 128，initial GPU free 4GiB / live free 2GiB，known/reserved 2GiB 单列。
- 候选副本集：**同一份冻结候选列表**，不允许任何策略看到额外候选、额外路径、额外后备或额外 relay/压缩/组播能力。
- 合法后备：完整 DRAM 底本对所有策略可见且同等可用。
- 评分与依赖：同一个 `restore_plan` / `estimate_execution` 事件队列，同一目标执行语义（含目标 worker 兼任 source 造成的前序阻塞）。

### 3.2 必须先解决的可行性前提

**如果两个策略在冻结场景上选出完全相同的布局，就没有可比对象。** 因此场景筛选本身是一个明确的关卡：

- 场景必须事前构造出"简单规则会落入占位陷阱、交换/joint 会改选"的结构（参考 `case_active_r01` 的 P0/P1/P2/P3 与 pool0/pool1 关系），而**不是看到结果后搜索参数**。
- 参数只用有理数，不扫描；一旦冻结，任何"再调一下让它有区分度"都算新的预登记轮次。
- 每个场景必须满足：所有候选在两个以上合法布局中都有非平凡使用证据，且没有用隐藏禁路制造差异。

### 3.3 场景数量的上界

单次完整恢复约 1.3–4.6s 在线时间，但前后准备、全 SHA、物理 park 与回收使每请求的墙钟成本远高于此。按资源与收敛需要，事前登记：

- 场景数 ≤ 2 个（一个远端主导、一个本地/混合主导，或一个交换敏感、一个瓶颈均衡敏感）。
- 每个场景每个策略一次正式测量；**外加同布局重复一次用于估计运行间波动**，重复不得用来挑选更好的一次。
- 总完整恢复请求数上界 **8**，超出需用户重新授权。

## 4. 策略集（全部在同一候选/预算/执行器下）

| 代号 | 定义 | 实现位置 |
| --- | --- | --- |
| `base_only` | 只用完整 DRAM 底本，额外 HBM = 0 | 现成 |
| `fastest_seq` | 固定 rank 顺序逐块选可行最快来源，与后备比较，不为慢于后备的候选建缓存 | `planning.restore_plan(strategy="fastest"/"nearest")` |
| `balanced` | 单步瓶颈均衡，允许零收益前进以越过平台期 | `strategy="balanced"` + 现有均衡参考 |
| `strong_simple` | 原 singleton/paired 边际贪心（gain>1e−9，密度优先） | `main_lib/fluidckpt/benchmarks/frozen_layout.py:94` |
| `exchange` | 冻结的一删一加、至多二删二加局部邻域，允许可行"删一加二" | `case_active_r01` 的交换参考 |
| `joint` | 原 MILP + 原路由 | `main_lib/fluidckpt/cluster/multi_joint.py:17` |

规则：

- `strong_simple` 的零收益平台期风险**必须显式保留**，不得为了让基线更强而私自放宽（那会偷换对照组身份）；同时必须报告 `balanced` / `exchange` 的存在，用来回答"是 joint 赢了，还是只是弱贪心输了"。
- `joint` 的 fallback 不得被计为 joint 成功：`restore_plan` 在 LP 不可行时会退回 `nearest`，此时必须记录 `fallback_reason` 并把该次标记为非 joint 结果。
- MILP 与 LP 的求解时间必须单独记账，见第 5 节。

## 5. 主指标与计时协议（本轮最关键的方法问题）

### 5.1 三个时间分量必须分开登记

10/23 归档核验已明确：`simple_controller.py:200` 附近的**恢复前 park 证据、资源门、command 控制文件发布发生在 `begin` 之前**，不在此前登记的 10% 资格窗口内；inventory、plan、物化/接管、复制、ACK 在窗内。

因此本轮**不得**直接复用旧窗口口径，也**不得**把排除项写成 0 成本。定义：

| 分量 | 区间 | 说明 |
| --- | --- | --- |
| `T_pre` | 请求到达 → `begin` | parked evidence、资源门、command 发布等每请求必要前置项 |
| `T_plan` | 规划器调用入口 → 布局决策返回 | 含 `planning_s`、MILP/LP 求解时间；必须实测并单列 |
| `T_exec` | `begin` → 完整 resume ACK 且全部 rank `weights_ready` | inventory、物化、IPC 接管、复制、同步、barrier |
| **`T_ready_total`** | `T_pre + T_plan + T_exec` | **主指标** |

所有策略用同一 `T_pre` 口径测量；若某策略因实现差异绕过某项前置工作，必须显式说明并同等扣除，不得默认其更便宜。

### 5.2 决策质量与执行质量分开

- **决策质量**：在冻结成本模型下，某策略选择的布局的预测 `T_ready_total` 与最优已知布局（有限候选内的 oracle，或 joint 解）之差。
- **执行质量**：同一布局的预测 vs 实际误差——沿用已验证的 10% 尺度，**不新增更严的门**。
- 二者不可混淆：joint 决策更优但执行误差更大时，如实分列。

### 5.3 成本模型的可用边界（必须先核，否则整轮无效）

当前模型资格只覆盖：登记路径域（6 路径 × 2 尺寸）、`post_one_fullrestore_samecontroller`。

因此：

- 候选布局**只能落在已登记的 6 条路径与 2 个实际尺寸上**。任何新路径/新尺寸候选必须先补校准，否则该候选标记 `unqualified`，不得进入实机比较。
- 所有实机请求必须在**同一个 controller 进程**内完成；首个请求单列不拟合（沿用 `C0_prime` 处理），至少一个后续请求用于冻结前校准。
- 首次恢复、新 controller、三节点多卡/SSD/多 NIC 共享域本轮不外推。

- 若资源门或前置条件失败，记为失败事实并停止，不降门槛、不挪用他在跑任务的资源。

## 7. 验收与停止规则

### 7.1 分阶段门

**门 1（CPU，无 GPU）：合同冻结。** 所有策略在同一候选集、同一预算、同一评分下产生合法布局；121/256 subset 级别的合法性复算通过；`strong_simple` 与 `exchange` 的行为与报告38一致。

**门 2（CPU，无 GPU）：区分度。** 至少一个场景中，两个策略选出的合法布局**不同**，且预测 `T_ready_total` 之差达到事前登记的最小决策间距 Δ。

**门 3（实机）：执行与正确性。** 预注册请求数内，全部 SHA/参考输出/物理 park/预算/回收通过。

**门 4（实机）：决策价值。** 同场景下两布局的实际 `T_ready_total` 差异方向与冻结预测一致，且幅度超过运行间波动。

### 7.2 Δ 与波动的处理

- Δ **已由用户于 2026-10-25 确认**为 `max(100ms, 5% × T_ready_total)`，冻结后不得依据实际结果回头修改。理由是当前模型单点误差量级为 −0.19%～−6.04%，几十毫秒的差无法可靠排序。
- 运行间波动用重复请求估计；若重复间差异 ≥ Δ，则本轮判为**无法排序**，只报告区间，不宣布胜者。

### 7.3 停止规则

1. 门 2 未过（所有场景布局相同）→ **停止，不启动实机**，记录为负结果：在当前候选/预算下两策略无决策差异。
2. 门 2 过但预测差 < Δ → 不启动实机，同判"差距过小，现有模型无法可靠排序"。
3. 门 3 失败 → 记录原文失败事实并停止，不追加请求救门。
4. 门 4 中 joint 未胜或仅追平强简单 → **如实记录 joint 无独有增量**，不扩 solver、不追加场景找胜例。
5. 门 4 中 joint 胜出且超过 Δ → 可主张"在登记场景与登记策略集内存在可测收益"，同时必须给出求解开销占比。

## 10. 建议的执行顺序（待讨论确认）

按"最便宜的证据先出、最贵的资源最后用"排序，任一阶段不过就停：

**阶段 0 — 口径冻结（CPU，0 GPU）**
确认 Δ、场景数、重复数、`T_pre` 归属方案（第 5.1 节）。产出本文的附录修订，不写代码。

**阶段 1 — 场景合同（CPU）**

**阶段 2 — 离线策略对照（CPU）**
六个策略跑同一合同，回答门 2：布局是否不同、预测差是否 ≥ Δ。**若相同或过小，整轮到此结束**，这是最可能的负结果出口，成本最低。

**阶段 3 — 成本可用性复核（CPU）**
检查入选布局是否全部落在登记 6 路径 × 2 尺寸内；任何越界候选标记 `unqualified` 并退回阶段 1。

**阶段 4 — 资源 re-admission（读现场）**
10/12 终态**不是**当前空闲证明。做一次 fresh 准入：目标两卡 free、helper free、GPU 身份/NUMA、外部 GLM/他人在跑任务。不通过就等，不放宽预算。

**阶段 5 — 源码冻结与 CPU 审查**
新源码快照、资产冻结、`decision_core/ops/review` 各自 CPU 检查通过，才有资格启动实机。

**阶段 6 — 实机单会话 ≤8 请求**
`C0_prime` → `C0_cal` → freeze → 对照请求 → 重复项。主会话统一 GPU。

**阶段 7 — 独立审计与结案**
误差、波动、决策价值、求解开销占比；写报告51，更新 `next_step.txt` 顶部。
正确性/回收失败一律原文保留，不改判。

## 11. 已知陷阱（写在这里是为了后面不被它们的变体骗到）

1. **共同 outer 不产生排序优势。** 它同等地加在所有候选上；只有路径/DAG/布局项才可能拉开差距。任何"joint 因为 outer 更好而赢"的说法都是错的。
2. **单次样本不是置信区间。** 10% 是验收尺度，不是统计保证。差值接近 Δ 时必须说"分不出"。
3. **目标 worker 兼任 source 会串行化。** 早先接收会阻塞后续发送；单路径速率排序不能替代完整计划比较。
4. **共享出口只能算一次。** 不要因为两条路径看似独立就把共享 U 复制成两条边。
5. **零收益平台期真实存在。** strict-positive 单步规则在 m>k 时无法起步（命题2）；`balanced` 必须留在对照集里，否则会把"弱贪心失败"错记成"joint 优势"。
6. **LP fallback 会伪装成 joint。** `resource_lp` 不可行时退回 `nearest`，必须检查 `fallback_reason`。
7. **10/12 的机器状态不是今天的状态。** 任何"上次跑得通所以现在能跑"的推断都要用 fresh 准入替代。
8. **计时窗口不可跨轮复用。** 10/23 已确认 park 证据/资源门/command 发布在 `begin` 之前；旧窗口不能直接当成本轮的 `T_ready_total`。
