# 两个无效候选的必要契约修订

开发号v0.1.23.3/task2。本文在首次修订实例求解之前登记。原`case_cpu_r03`的两rigid内容r2/r3在pool1的速率0.5被完整DRAM后备速率1支配；121个合法布局均不取用这两候选，未满足每块两个有意义位置。原件与失败完整保留。

只将r2/r3的pool1速率设为共同符号参数v，其余候选、底本、位置cap、队列、baseline规则、额外额度、role复用、成本函数保持原r03。此变更是修复候选活性契约，不以joint胜出为目标；简单exchange已与joint同解。

要使这两个位置严格快于底本，必要条件为v>1。容量感知最快按rank顺序先放r0@pool0、r1@pool1、r2@pool0、r3@pool1。若原路由的整块来源使用这些cache，rank-interleaved顺序是local0、local1、pool0→r2、pool1→r3；最后两个分别在0.25开始，时长0.25和1/v。故当v<4时，其符号服务完成为0.25+1/v。

交换布局为r0/r1@pool1、r2/r3@pool0。pool1先向target0传输1/3，再在自身恢复rank1的local操作1/4；pool0在接收rank0的1/3后，串行发送r2/r3，各1/4。目标最后receiver时间分别1/3、7/12、7/12、5/6，整体为5/6。

使交换布局比最快队列更快的充分不等式是1/4+1/v>5/6，即v<12/7。结合候选活性得非空区间1<v<12/7。冻结一次v=3/2，则最快显式cache队列为11/12，交换显式cache队列为5/6，两者实际cache均16MiB；各pool各两块。不得继续扫描区间或调参数寻找joint赢。

完整DRAM后备继续参与所有策略的原resource_lp路由。上述队列公式是显式来源假设下的推导，不能先验代替原LP输出：原LP对非关键rank可能存在流量tie，4MiB路由量子取整可能选择不同来源。例如v=3/2时，rank0仅靠target串行约束只需local占比至少4/9，不能单凭该约束保证local流为多数。修订实例必须输出实际来源、字节、依赖和timeline并独立验证上述公式是否适用；不适用时保留失败而不扫参数。

验收包括：参数仅两项变更；全部121个合法复制布局保留；八个候选各至少在一个合法布局被原共同路由使用；每块两个保存位置活性成立；强baseline全部机会相同；同额度和实际16MiB缓存对照；shared-resource事件负载检查；simple-exchange与joint同解仍如实记录。物理速率、runtime、模型binding和实际权重ready全部未知。
