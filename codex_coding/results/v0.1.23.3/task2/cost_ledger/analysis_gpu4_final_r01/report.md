# GPU4八请求成本探索最终解读

实际恢复中，完整搬运执行约0.43–0.76ms，包含准备等工作的filled约8.19–10.27ms，全SHA校验发布约118–313ms。现在已能按真实边界解释这些钱花在哪；尚未得到可正式保留的完整恢复预测模型。三项候选在两个新会话点通过worker/controller/filled误差门，可保留局部worker预测资格；完整模型按预先冻结的复杂度门未通过。

六校准请求和新会话V2/V1共八请求已经结束，不增加第三会话或新参数救模型。原GPU0资源门失败为0校准请求；GPU4两成功会话各96MiB source bootstrap另列，测量payload512MiB、15op、20copy/sync，bootstrap共192MiB，不含SHA/HTTP等额外流量。这里无新GPU/SSH/solver操作，未改冻结源码、预测、系数或门槛。

留出前最简单worker `a+bN` 的V2误差−149.282µs（−19.64%）通过；V1误差−196.513µs（−27.66%）未通过20%相对门，虽然绝对误差小于250µs。简单模型两点外层门通过，不会覆盖这个局部失败。V1只有48MiB，但K=3的worker .710370ms高于训练L2的64MiB/K=1 .518466ms；这说明在本次K=3留出中仅按字节的聚合不足，不能把这个对比唯一归因为某个底层函数。

三项worker候选在两个点的worker误差+0.45%/−6.16%，controller−4.41%/−2.19%，filled+0.65%/−16.32%，各自同时满足固定绝对与20%相对门；局部worker候选资格为 `a_bN_cK`。候选逐层通过和最终模型保留是两项验收。

为什么完整模型仍不保留：预声明要求更细模型相对留出前简单模型，在每个点和每一相关层都改善超过该层C1观察尺度，即worker/controller E=83.030µs，filled E=575.449µs。

三项候选因此为 `complexity_increment_unproven`；`selected_worker_and_outer=null`，`complete_filled_model_qualified=false`。这保留局部三项候选的独立误差门资格，同时拒绝宣称复杂度已带来可辨的完整请求预测收益。小样本结果不是未来误差界，也不授权亚ms布局排序。

独立service边界也没有合格保留模型：简单候选两点绝对误差105.286/144.594µs，均超过固定50µs；三项service系数为192.649167+2.92378125N+59.108167K µs，V2误差−10.713µs通过，V1误差−50.020833µs，严格超过50µs门约0.020833µs（20.833ns），按原门失败，不能显示舍入成50µs后改判。四项service及worker在留出部分数字准确，但C1 c/d/32b细信号未过，原admissible=false；留出不能反过来批准已拒绝结构。

## V1的1.676ms低估主要在哪里

三项filled预测8.595478ms，实测10.271848ms，低估1.676370ms，可按同一冻结账拆成：worker低估0.043790ms + controller−worker残差增加0.010528ms + filled−controller残差增加1.622052ms。最后一项占约96.8%。这不是新增DMA/设备带宽成本。

C1 frozen `filled−controller` 的中位数6.166163ms恰来自L2；直接比较原件L2与V1可定位最后这1.622052ms，未重新拟合：

| --- | ---: | ---: | ---: |
| 实际inventory RPC | 3.353945 | 4.741324 | +1.387379 |
| 实际prepare RPC | 2.007327 | 2.161269 | +0.153942 |
| 其余请求窗/边界剩余 | 0.804891 | 0.885622 | +0.080731 |
| filled−controller合计 | 6.166163 | 7.788215 | +1.622052 |

inventory/prepare合计增量1.541321ms，其余窗口增量0.080731ms；这里定位到具体请求窗口，尚未唯一识别inventory内部、调度、HTTP或准备分配的底层原因。对比使用原中位点，不把这些V1残差回填到预测。controller−worker只增加10.528µs，不能把1.676ms统称execute dispatch误差。
