## 4. 规范的关键决定

1. 一份完整计划对应一份实验总记录；记录内逐 eN 建章节，未来逐 run 追加完整报告。过长可以拆附件，但保留总入口和链接。
2. 新实验脚本和原始数据使用 `.3/task2/paper_e1_e8/eN` 命名空间，run_id 永不复用。已存在的脚本可按真实路径复用。
3. 报告必须写关键数据表、原始数据映射、实际命令、错误和结论边界；不能只有“passed”。执行、功能、科研和性能状态分开。
4. 底本/缓存、临时峰值、预留及提前准备开销均记账；不混用传输、权重可用和首 token 指标。
5. e8 为条件性实验；没有必要性证据时允许 deferred。不会因工程上有缺口就默认补齐。
6. 正式 e1–e8 运行数为 0。旧数据只作为历史背景，不能转写成新系列实测或已完成状态。
